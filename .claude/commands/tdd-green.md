Kent Beck TDD의 **Green 단계**를 마일스톤 단위로 수행한다. `CLAUDE.md`의 TDD 규칙을 따른다.

대상 마일스톤: $ARGUMENTS (비어 있으면 `TDD-IMPLEMENTS.md`에서 Red는 체크, Green은 미체크인 마일스톤)

## 절차

1. `TDD-IMPLEMENTS.md`에서 대상 마일스톤과 Red 기록을 확인한다. Red가 없으면 중단하고 `/tdd-red`를 먼저 실행하라고 안내한다.
2. 전체 테스트를 실행해 **실패하는 테스트가 이 마일스톤의 테스트뿐인지** 확인한다 (`npm test` 또는 `node --test`).
3. 테스트를 **하나씩** 골라 통과시키는 최소한의 코드를 작성한다. 하나 통과할 때마다 테스트를 다시 실행한다.
   - 하드코딩, 중복, 임시 구조가 있어도 괜찮다. 이 단계의 목표는 통과다.
   - 마일스톤 테스트가 요구하지 않는 기능·분기·옵션을 추가하지 않는다.
4. 마일스톤의 모든 테스트가 통과하면 **전체 테스트**를 실행한다. 기존 테스트가 깨지면 구현을 고친다. 테스트를 수정해서 통과시키지 않는다.
5. `TDD-IMPLEMENTS.md`에서 해당 마일스톤의 Green을 `[x]`로 체크하고, "기록: Green"에 구현 파일과 남은 정리 대상(하드코딩, 중복)을 "Refactor 후보"로 적는다.

## 금지

- 테스트 코드를 약화하거나 삭제하지 않는다.
- 리팩터링을 하지 않는다 (`/tdd-refactor`에서 한다).
- 테스트가 실패하는 상태에서 커밋하지 않는다.
- 다음 마일스톤의 기능을 미리 구현하지 않는다.

## 종료

통과한 테스트 수, 변경한 파일, Refactor 후보를 보고하고, 다음 단계로 `/tdd-refactor`를 안내한다. 사용자가 요청하면 행위적 커밋(`feat:`/`fix:`)을 만든다.
