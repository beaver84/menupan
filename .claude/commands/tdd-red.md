Kent Beck TDD의 **Red 단계**를 마일스톤 단위로 수행한다. `CLAUDE.md`의 TDD 규칙을 따른다.

대상 마일스톤: $ARGUMENTS (비어 있으면 `TDD-IMPLEMENTS.md`에서 Red가 체크되지 않은 첫 마일스톤)

## 절차

1. `TDD-IMPLEMENTS.md`를 읽고 대상 마일스톤 **하나만** 선택한다. 이전 마일스톤의 Refactor가 끝나지 않았다면 중단하고 사용자에게 알린다.
2. 마일스톤의 "테스트 케이스" 목록 **전체**를 테스트로 작성한다.
   - 케이스 1개당 테스트 1개. 테스트 이름은 동작을 설명한다 (예: `품절이 Y면 soldOut이 true다`).
   - 파일 경로, 시간, 포트, 감시자 같은 외부 의존성은 주입한다. 실제 `data/menu.xlsx`에 의존하지 않는다.
   - 목록에 없는 케이스가 필요하다고 판단되면 `TDD-IMPLEMENTS.md` 해당 마일스톤에 먼저 추가한 뒤 작성한다.
3. 마일스톤 테스트 파일을 실행한다: `node --test <파일들>`
4. **모든 신규 테스트가 올바른 이유로 실패하는지** 확인한다.
   - 구현 부재(`not a function`, import 실패)나 단언 불일치는 정상 Red다.
   - 문법 오류나 테스트 자체의 버그로 실패하거나, 구현 없이 우연히 통과하는 테스트가 있으면 테스트를 고친다.
5. `TDD-IMPLEMENTS.md`에서 해당 마일스톤의 Red를 `[x]`로 체크하고, 케이스 체크박스를 `[x]`로 바꾸고, "기록: Red"에 테스트 파일과 실패 요약을 적는다.

## 금지

- 프로덕션 코드(`src/`, `server.mjs`, `public/`)를 수정하지 않는다. 테스트 실행용 빈 스텁도 만들지 않는다(import 실패를 Red로 인정한다).
- 다른 마일스톤의 테스트를 미리 작성하지 않는다.
- Red 상태에서 커밋하지 않는다.

## 종료

작성한 테스트 수와 실패 이유를 보고하고, 다음 단계로 `/tdd-green`을 안내한다.
