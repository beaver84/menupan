Kent Beck TDD의 **Refactor 단계**와 **Tidy First**를 마일스톤 단위로 수행한다. `CLAUDE.md`의 규칙을 따른다.

대상 마일스톤: $ARGUMENTS (비어 있으면 `TDD-IMPLEMENTS.md`에서 Green은 체크, Refactor는 미체크인 마일스톤)

## 절차

1. 전체 테스트를 실행해 **모두 통과(Green)** 인지 확인한다. 하나라도 실패하면 중단하고 `/tdd-green`으로 돌아가라고 안내한다.
2. `TDD-IMPLEMENTS.md`의 해당 마일스톤 "Refactor 후보"와 이 마일스톤에서 변경된 코드를 검토한다.
3. 다음을 찾아 정리한다.
   - 하드코딩된 값 (매직 넘버, 고정 경로, 고정 시트 이름은 상수·인자·설정으로)
   - 중복 코드
   - 의도를 드러내지 못하는 이름
   - 한 함수가 여러 책임을 가짐, 긴 함수
   - 암묵적 의존성 (파일 경로, 시계, 포트, 감시자는 주입 가능하게)
   - 불필요한 상태·부수효과
4. **구조적 변경만** 한다. 동작을 바꾸지 않는다. 새 동작이 필요해 보이면 `TDD-IMPLEMENTS.md`에 케이스나 마일스톤으로 추가하고 이번에는 하지 않는다.
5. 작은 리팩터링 하나를 할 때마다 **전체 테스트**를 실행한다. 실패하면 즉시 되돌린다.
6. `TDD-IMPLEMENTS.md`에서 해당 마일스톤의 Refactor를 `[x]`로 체크하고, "기록: Refactor"에 수행한 정리를 적는다.
7. 커밋 조건을 확인한다: 모든 테스트 통과, 경고 없음, 하나의 논리적 단위.
   - Red+Green 변경은 행위적 커밋(`feat:`/`fix:`), Refactor 변경은 구조적 커밋(`refactor:`)으로 **분리**한다.
   - 사용자가 커밋을 요청하지 않았다면 커밋하지 말고 제안만 한다.

## 금지

- 테스트를 수정해 통과시키지 않는다. (테스트 이름 변경 등 구조적 정리는 가능하나, 단언 내용은 바꾸지 않는다.)
- 구조적 변경과 행위적 변경을 한 변경에 섞지 않는다.
- 이 마일스톤과 무관한 코드를 정리하지 않는다.

## 종료

정리한 내용과 테스트 결과를 보고한다. 다음 미완료 마일스톤이 있으면 `/tdd-red`를 안내한다.
